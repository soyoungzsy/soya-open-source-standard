# 引用、原作者与许可证 / Sources, authors and licenses

## 必须做的事

1. 检查当前文件、完整 Git 历史、已有 README、LICENSE、NOTICE、包清单、依赖锁文件和素材说明，找出真实来源。不要只检查 GitHub 的 fork 标记；下载 ZIP 或复制 Skill 后改造也属于有上游来源。
2. 区分：基于原项目改造、直接复制代码/说明/Prompt/Skill、使用素材、仅受方法启发、运行时依赖。没有证据时写“来源待核实”，不猜作者，不声明全部原创。
3. 在中英 README 增加容易找到的“来源与致谢 / Sources and acknowledgements”，链接项目内的 SOURCES.md 或已有 NOTICE。已有规范文件优先更新，不制造互相矛盾的重复清单。
4. 每个来源记录原作者的公开署名、原项目/Skill 名称、公开链接、采用的版本或提交（无法确认时明确写出）、关系类型、使用的文件或方法、本项目实际改动、许可证及其文件链接。
5. 保留原版权声明、许可证全文和必要 NOTICE。Soya 署名是对本人的默认脱敏规则，不能抹去第三方公开署名。不能将他人的全部成果重新署名为 Soya。
6. 不能因为“开源、公开可见、注明出处、AI 改写”就推定有权复制或重新许可。没有许可或许可条件不明时，暂停受影响内容的发布；取得许可、替换为独立实现或移除后再审。涉及许可兼容性的疑问保留待核实，不能编造法律结论。
7. 下载包、Skill 安装包、导出素材及网站等实际分发物也必须保留适用声明；只在 GitHub 首页感谢不够。依赖清单中的第三方库和素材分别记录，不把参考灵感说成代码改造，也不把代码改造淡化为灵感。
8. 检查引用链接有效且指向真正的原项目；不得暗示原作者为本项目背书。不得用此步骤搜集原作者的私人姓名、邮箱或工作信息。每次更新重新检查新增、移除和变更的来源。

## 可直接填写的来源表

| 原项目或素材 | 原作者公开署名 | 公开来源 | 版本或提交 | 使用方式与范围 | Soya 的改动 | 许可证与保留声明 |
|---|---|---|---|---|---|---|
| 填真实项目名 | 按原项目声明 | 原项目链接 | 已核实值或“未能核实” | 改造/复制/素材/启发/依赖，并列文件 | 具体描述 | 许可证链接及包内声明路径 |

不得把模板行当成已核实的来源。没有发现来源不等于原创保证；记录检查范围和无法确认的部分。

## 非技术读者应该看懂什么

用一句普通话说清：“这个项目基于谁的什么做了哪些改进；原作者做了什么，Soya 又做了什么。”给读者能点开的原项目链接。许可证细节放在后面，但不能省略。

## 发布后验收

- 中英首页能找到来源入口，来源身份和实际改造关系一致。
- 固定版本中的源码、说明包和适用素材保留原版权、许可证与 NOTICE。
- 来源未核实、未授权内容或许可冲突未解决时，不标记此项通过。
- 不移动旧 tag；修正缺失声明后发布新版本，并公开记录修订。

## English

Identify actual sources from current files, full Git history, existing credits, licenses, notices and dependency manifests. A ZIP download or copied Skill still has an upstream source even without a GitHub fork flag. Distinguish derivatives, copied code/text/prompts/Skills, assets, inspiration and dependencies. Record the original public author, project, URL, verified revision (or an explicit unknown), reused scope, Soya's changes and license obligations. Preserve required copyright, license text and notices in every applicable distributed package. Public availability, attribution or AI rewriting does not itself grant reuse rights. Unclear provenance or permissions block the affected publication until resolved. Explain the relationship plainly in both READMEs; do not imply endorsement or collect private author information. Recheck sources after every update and after publication.
