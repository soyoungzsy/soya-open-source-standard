# Soya 项目开源规范

## 为不会编程的你准备

这是一份给 AI 的“开源项目发布说明包”（Skill）。你把自己的方法交给 AI，它按规范帮你写清介绍、检查隐私、整理使用步骤，并在有权限时完成发布。你不需要先学会写代码。

推荐先用下方“复制给 AI”：打开你平时使用的 AI 聊天工具，复制整段指令，填上一个可公开的小方法并发送。你应得到项目说明、使用示例、隐私检查和下一步清单；缺少事实时 AI 应提问。AI 工具可能收费，不要输入公司资料、密码或私人信息。

后面出现的“仓库”就是项目在 GitHub 上的页面；“PR”是等待审查的修改提案；“Release”是可下载的固定版本。不会安装时先用复制指令即可，后面的完整安装是可选步骤。



**让 AI 把你的个人方法、经验和工具，整理并发布成陌生人看得懂、用得上、经过脱敏检查且可持续维护的 GitHub 项目。**

Turn personal methods and tools into understandable, usable, privacy-reviewed GitHub projects with verifiable releases.

[English](README.en.md) · 当前版本：0.2.1 · 初始试用版；发行状态以仓库 Releases 为准

## 先试一次：复制给 AI

无需安装，复制下面内容到你正在使用的 AI，再附上有权公开的方法或项目。此路径提供轻量检查；完整执行请使用 Skill。

```text
请按 Soya 项目开源规范整理我提供的方法或项目：
1. 标题包含 Soya，中英各一句说清功能。
2. 中英分别完整说明背景、场景、用户、输入输出、成本和限制。
3. 提供新手最短使用路径：完整可复制 Prompt，或经验证的安装和调用步骤。
4. 默认仅保留 Soya 署名；排除私人身份、工作信息、内部数据、链接、代码及凭据；例子用合成数据。换名不等于可公开，权利不清的材料剔除。
5. 补齐示例、许可证、版本、更新记录、问题处理和实际可行的回滚路径。
6. AI 后续修改使用分支和 PR，保留变更与测试；仅提报不自动合并。
7. 我明确要求发布时继续做到公开仓库、固定 tag、正式 Release 和公开获取验收；仅建仓或 push 不算完成。
8. 所有对外文档默认写给不会编程的人：先讲用途和例子，逐步说明在哪里操作、点什么、输入什么、成功看到什么、出错怎么办；术语先解释，开发细节放后面。每次真实发布后，以首次接触的第三方视角重新检查公开内容，列出疑问、修订并复查；未完成不能标记已验收。
9. 只在授权范围操作，不编造测试、安装命令、链接或发布成功；有阻塞说明实际状态和最小解除动作。
输入：[在这里附上有权公开的方法或项目]
本次目标：[仅整理 / 修改提报 / 发布 GitHub / 发布在线应用]
```

## 为什么做

个人已经在使用的方法，值得整理成别人也能复用的产品。但 AI 容易只生成说明、留下空仓库，或遗漏真实安装、工作信息脱敏、版本和维护。本 Skill 将这些要求放进同一工作流程，用实际证据判断交付完成。

## 适合谁、用于什么

适合独立创作者、非技术 AI 使用者和 AI Builder，将个人方法、Prompt、Skill、脚本、扩展或小应用开源；也适合让 AI 为已有项目修改提 PR 和发布版本。

不替代公司开源审批、知识产权判断或专业安全审计；不用于把内部资料简单改名后公开。不提供 GitHub 权限或自动运行的后台机器人。

## 一个合成示例

输入：“我每周用三个问题回顾阅读笔记，想让别人也能用。”

输出应包含：Soya 阅读回顾项目定位、中英介绍、可复制的三问 Prompt、合成笔记与输出示例、适用边界、0.2.1 版本、维护说明。只有用户要求并具备发布权限时才实际发布；缺少权限时报告阻塞，不能输出虚构链接。

这是预期结果示意，不是已运行的案例或用户证言。

## 可选：安装完整说明包（不会安装可以跳过）

如果你只想先试一次，使用上面的复制指令即可。下面供想安装完整说明包的人或协助安装的人参考。

文件夹结构：SKILL.md 是执行入口，agents/openai.yaml 是界面元数据，references 是按需读取的详细规范。必须保留整个目录。

最简单的方法：把完整文件夹或这个项目的 GitHub 链接交给支持 Skill 安装的 AI 助手，发送：

```text
请安装 soya-open-source-standard：先检查目录内容，核实当前 AI 工具的 Skill 安装机制，备份同名旧版，再安装并验证新会话可以发现它。不要覆盖我的用户配置，不要运行不必要脚本。
```

离线安装：在[版本下载页](https://github.com/soyoungzsy/soya-open-source-standard/releases)选择版本，点 Source code (zip) 下载压缩包，解压后把包含 SKILL.md 的完整目录放入 AI 工具支持的技能目录，再重启或新建会话验证。普通聊天窗口未必支持 Skill 安装；不支持时使用上面的轻量 Prompt。

安装后发送：

```text
使用 $soya-open-source-standard，把这个项目整理并发布到我指定的 GitHub 仓库。完成中英介绍、新手入口、脱敏检查、版本和公开发布验收；遇到阻塞报告准确状态。
```

成功标准：助手按七个步骤工作，报告真实证据，并能区分“本地完成”和“公开发布完成”。仅看到它重复规范不代表安装验证成功。

## 成本、数据与限制

规范本身无额外服务费用；需要自己的 AI 工具和 GitHub 账号，AI 使用、自动检查或网站托管可能另外收费。只对用户授权的项目工作。不要输入工作机密、密钥或个人敏感信息；AI 工具及第三方服务的留存政策各自适用，本项目不保证零留存。

不包含联网或发布脚本，不自动收集数据。v0.1.0 已实际公开发布，11 个文件与审查稿逐一核对一致；已重新阅读公开中英介绍并发现需要强化非技术用户入口，本版据此修订。AI 工具安装与完整 AI 自动执行仍未验证。

## 更新、卸载与恢复

升级前备份同名目录；选择固定版本并替换完整目录，保留 AI 工具配置。异常时恢复旧目录并新建会话。卸载只移除本 Skill 目录，不删除项目和用户数据。项目本身的代码、部署和数据恢复分别按配套规范处理。

## 遇到问题

无法发现 Skill：检查目录层级与 SKILL.md，确认 AI 工具支持并重开会话。无法发布：核对目标账号、权限与网络；不要把访问凭证（相当于密码）发进聊天。提问时说明项目版本、使用的 AI 工具、你做了哪些操作，并附上去除私人和工作信息后的报错内容，不上传私人或工作资料。当前未设置独立支持渠道，不承诺响应时间；普通问题可使用仓库 Issues（公开提问区）；私密漏洞报告渠道尚未验证，请勿在公开 Issue 粘贴敏感信息。
